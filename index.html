    How this is built

    • Downloads themselves are paywalled at Apptopia. Its Performance, Rank History and Audience pages need a subscription. What is public is its daily top charts (any date, via ?date=) and what it tells journalists.
    • Google Play installs are Google's own count (the number behind the "100,000+" / "500,000+" label on the listing). They are global, but Muse is only live in the US and Canada. History before this tracker began comes from Wayback Machine captures of the listing.
    • Google's install count seems to lag. The 2026-09-11 capture shows 567 ratings on only 2,113 installs, which can't both be current (the later ratio is about 30 installs per rating). Rating counts update live; the install count seems to refresh every few days. Daily Google Play values are therefore smoothed and may trail real installs.
    • App Store ratings come from the rating count in each store page's structured data. Apple's lookup API reports a stale count (38,599 against 43,807 on the page on 2026-09-25), so it is logged but not used.
    • Daily values are linear interpolations between captures, at the end of each UTC day. Captures are marked on the lines. Paler bars and "interpolated" in a tooltip mean the value spans a multi-day gap.
    • Firm vs Google: a firm's Android figure is compared with Google's count at the end of the firm's window. If a firm only gave a total and an iOS number, Android = total − iOS.
    • Refresh: a Windows scheduled task (Muse Download Tracker Daily) runs update.py, which collects data, then rebuilds this page. No Claude needed. Data: data/*.csv.
